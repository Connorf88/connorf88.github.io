Approach

How I work when nobody is watching

I'm early in this. What I can tell you is how I've chosen to build so far, and why.

01 · Automate

If I did it twice by hand, it becomes a script

Manual steps are where mistakes hide, and they're invisible until the person who knew them is out sick. Deploying OutageWatch used to be four terminal commands I ran in a particular order. Now it's a push, and the order lives in a file anyone can read.

02 · Verify

A deploy isn't done until something checks it

"It came up" is not the same as "it works." Every release runs a health check that asserts the specific things that break: database reachable, cache responding, certificate not expiring, endpoint returning what it should. If that check fails, the pipeline moves the traffic back before I've noticed.

03 · Write it down

The runbook gets written before the outage

Documentation written during an incident is written by someone panicking. I write the recovery steps while the system is calm and I still remember why it's built this way, then I test them by actually breaking things in staging.
